# 004 — MCP: SDK e transporte

Data: 31/10/2026 · Situação: aceita

**Contexto.** O TCC 1 cita "SDK oficial do MCP em Python" e "Node.js como linguagem
principal" na mesma frase. O projeto adota Node.js como único runtime.

**Decisão.** SDK oficial `@modelcontextprotocol/sdk` (TypeScript). Servidor expõe uma
tool de busca por fonte e o host descobre as tools com `tools/list` antes de chamar.
Transporte **stdio** no experimento (sem rede no meio da medição); Streamable HTTP
opcional, só para a demonstração.

**Consequências.** A troca de Python para TypeScript é declarada no artigo como
divergência do TCC 1 (ver `docs/metodologia.md`). A latência medida inclui serialização JSON-RPC e comunicação entre
processos, que precisa ser separada do custo da busca na análise.

**Implementação (31/10/2026).** Servidor em `src/mcp/server.ts`, com tools `buscar_<fonte>`
(entrada `consulta` e `k` de 1 a 50, saída estruturada `resultados`) e anotação somente
leitura. O processo stdio (`src/mcp/stdio.ts`) é configurado por `MCP_SOURCES`,
`MCP_EMBEDDER` e `MCP_STORE`. O host (`src/approaches/d-mcp-rag.ts`) descobre as tools
com `tools/list`, chama todas em paralelo e funde por RRF; não tem nenhuma referência às
fontes no código.
